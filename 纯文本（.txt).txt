# Pet Guard (宠粮避雷针) 最终版 PRD

## 1. 功能需求（面向 Cursor）

### **用户故事**

> “作为一个在超市或宠物店面对陌生宠粮的宠主，我希望能直接拍摄包装袋背后的配料表，让系统立即告诉我这份粮是否含有风险成分，并给出一个直观的健康分数，而不需要我手动输入。”

### **更新后的核心功能清单**

* **[核心筛选]**：支持按宠物种类、预算、特殊需求过滤已有数据库。
* **[健康评分算法]**：基于 `protein`、`meat_clarity` 等字段自动计算 0-100 的健康分。
* **[拍照识别配料表 (新)]**：
* 提供文件上传/摄像头调用入口。
* **识别逻辑**：前端接收图片流，模拟/调用 OCR 提取文字。
* **关键词扫描**：建立一个前端关键词库（Positive: 鲜肉, 冻干; Negative: BHA, 肉粉, 诱食剂）。
* **即时评估**：扫描提取到的文字，命中正向词加分，命中负向词扣分并生成“避雷提示”。


* **[测评存证 (新)]**：支持将本次 OCR 识别的结果及评分，临时保存到浏览器的 `localStorage`。
* **[对比引擎]**：支持将 OCR 识别出的数据与数据库中的现有产品进行左右分栏对比。

## 2. 界面布局描述（面向 Cursor）

### **页面结构与组件布局**

* **区域 1：全局导航栏 (Header)**
* 居左：标题 "Pet Guard"。
* 居右：**[新增] 动作按钮 "拍照识成分"**。


* **区域 2：筛选控制面板 (Filter Section)**
* 位于 Header 下方，横向排列：宠物类型切换、预算区间选择、核心诉求复选框。


* **区域 3：OCR 交互工作区 (OCR Workspace) - [新]**
* **触发态**：点击“拍照识成分”后，在筛选面板下方弹出一个全宽容器。
* **入口位置**：容器左侧为一个大的“上传图片/开启摄像头”虚线点击框。
* **结果展示位**：容器右侧为“实时识别区”，包含：
1. 顶部：巨大的数字评分（0-100）。
2. 中部：风险成分列表（红色文字标签）。
3. 底部：两个并列按钮——“保存记录”、“与库内产品对比”。




* **区域 4：金榜与全量列表 (Ranking & Grid)**
* 位于 OCR 区域下方。
* 包含 Top 3 推荐卡片和下方 4 列网格的产品库。


* **区域 5：对比模态框 (Comparison Overlay) - [更新]**
* 采用 **1:1 左右分栏** 布局。
* 左栏：展示刚才 OCR 识别的数据（配料、评分）。
* 右栏：展示用户从库中选择的现有产品数据。

## 3. 新增数据字段

为支持 OCR 和本地保存，需在数据模型中增加：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `ocr_raw_text` | String | 存储 OCR 提取的原始配料文字 |
| `scanned_risks` | Array | 命中的风险关键词集合（如：['BHA', '诱食剂']） |
| `is_user_upload` | Boolean | 区分是数据库自带产品还是用户拍照上传的产品 |
| `scan_timestamp` | Number | 拍摄/识别的时间戳，用于本地记录排序 |
| `local_records` | Array | 存储在 `localStorage` 中的用户识别历史 |

## 4. 开发顺序建议（Cursor 执行路径）

1. **第一步：基础框架与数据引擎**
* 建立 HTML 结构和 `mock_data.json`。
* 编写核心 `calculateHealthScore()` 评分函数。


2. **第二步：筛选与列表展示**
* 完成 Header、筛选逻辑及产品网格的渲染。


3. **第三步：OCR 模拟模块 (重点)**
* **指令**：“请创建一个图片上传入口，当用户上传图片后，延时 2 秒模拟识别过程，随机返回一段包含‘肉粉、BHA、鲜鸡肉’的 mock 文本，并触发评分函数。”


4. **第四步：关键词扫描器**
* 编写一个简单的正则匹配逻辑，扫描 OCR 文本中的预设关键词，更新 `scanned_risks` 列表。


5. **第五步：对比与本地存储**
* 实现将扫描结果推入 `localStorage`，并在对比弹窗中调用该数据。



---

## 5. 开发边界（防跑偏）

* **不要求真实 AI 模型**：OCR 部分如果 Cursor 无法直接调用外部免费 API（如百度/腾讯 OCR），请让它直接用“前端延时+假数据返回”来完成逻辑闭环。
* **不设服务器**：所有数据处理、图片解析逻辑均在前端运行，数据存储仅限 `localStorage`。
* **不处理图片存储**：用户上传的图片不需要保存到服务器，识别完文字后直接释放内存。
